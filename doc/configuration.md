# Internal configuration reference

**Audience: developers and advanced administrators.**

[Documentation index](README.md) · [Installation](installation.md)

The appliance generates player/web configuration through
[boot preferences](provisioning.md#allowlisted-preferences)
and channel setup. The generators in
[provision.py](../satip_appliance/provision.py) define appliance defaults.
**Backend UUIDs and device identities are not portable.** Examples illustrate
the schema; setup discovers the actual backend identities. See the
[sanitized configuration examples](../examples/README.md). JSON paths must be absolute.
This is a contributor schema reference, not a settings guide. Use
[Device settings](device-settings.md) for supported browser changes. Manual config
edits require restarting the affected supervisor-managed service. The player
reloads the web-managed library without restart.

## Player configuration

Schema: [config.py](../satip_controller/config.py); generated by
`player_config()` in [provision.py](../satip_appliance/provision.py).
All fields are required; unknown
fields are rejected. There are no implicit player-config defaults.

| Field | Example | Meaning / validation |
|---|---|---|
| `version` | `1` | Integer schema version, exactly 1 |
| `library` | `/var/lib/satip-management/library.json` | Catalogue and favourites |
| `credentials` | `/etc/satip-player/credentials.json` | Playback-only credentials |
| `state_dir` | `/var/lib/satip-player` | Durable private state; runtime status redirects under `SATIP_RUNTIME_ROOT` |
| `management_dir` | `/var/lib/satip-management` | Durable library context; runtime leases/EPG redirect under `SATIP_RUNTIME_ROOT` |
| `runtime_dir` | `/run/satip-player` | Lock, socket, auth include; mode 0700 |
| `drm_device` | `/dev/dri/by-path/platform-gpu-card` | Stable DRM identity |
| `drm_connector` | `HDMI-A-2` | Preferred connector on that device; falls back to the other connected Pi HDMI port |
| `drm_mode` | `1920x1080@50` | Explicit mpv output mode |
| `audio_device` | `alsa/hdmi:CARD=vc4hdmi1,DEV=0` | mpv ALSA device name |
| `keyboard_vendor` | `1241` | Integer VID 0–65535; hexadecimal 04d9 |
| `keyboard_product` | `6` | Integer PID 0–65535; hexadecimal 0006 |
| `grab` | `true` | Boolean exclusive selected-node grabs |
| `osd_ms` | `3000` | Ordinary message duration, integer 500–10000 ms |
| `repeat_delay` | `0.5` | Seconds before native volume repeats |
| `repeat_interval` | `0.125` | Minimum seconds between volume repeats |
| `debounce` | `0.08` | Minimum seconds between same-group/action presses |
| `load_timeout` | `20` | Seconds for useful playback readiness |
| `stall_timeout` | `10` | Seconds without advancing playback before retry |

With the supervisor's `SATIP_RUNTIME_ROOT=/run`, shared status goes
to `/run/satip-status`, leases/EPG to `/run/satip-management`, and preview media
to `/run/satip-web`. See [operations](operations.md#paths-and-permissions).

All five timing fields accept numbers from 0.01 to 120 inclusive. Device strings
must be nonempty without CR, LF, or NUL. Validation checks syntax, not physical
connector/audio operation.

HDMI connector/rate fallback and boot EDID handling are documented in
[HDMI startup](hdmi-startup-screen.md#hdmi-selection-and-handoff).

## Saved audio PID and live fallback

The library’s `audio_pid` remains the preferred main audio track on stereo output.
On multichannel PCM output, live normal German surround and Dolby tracks take
priority, including a Dolby track currently carrying stereo so a later surround
transition can be decoded. Normal German MP2, AC3, EAC3 and AAC are supported.
The live track must explicitly identify its codec, German language (`deu`, `ger`,
`de`), non-external origin and absence of visual/hearing impairment, with a valid
transport PID. Even a saved PID cannot bypass these checks. Equally ranked
ambiguous tracks and incomplete metadata fail closed. An already selected track
is not reselected, avoiding unnecessary decoder resets. Selection is checked
periodically during playback as well as on channel load.

mpv starts each TV load paused, probing audio and video together. Playback
unpauses only after a suitable normal German track is verified; language
preference alone must not permit audible foreign fallback. This retains early
audio packets rather than enabling audio after video has already started.
The initial-load gate does not unpause an existing time-shift pause. The
active standard Pi HDMI route uses an explicit PCM layout whitelist from valid
EDID LPCM descriptors at 48 kHz / 16 bit. Stereo is the safe fallback. Compressed
passthrough stays disabled and decoder-side downmix is disabled so the overlay
can distinguish the decoded source layout from the final output layout. There
is no new configuration field or library migration. See [HDMI audio](usage.md#hdmi-audio).

This is playback-only recovery: it does not change the saved library, favourites
or backend mappings. Refresh the channel catalogue and save the updated channel
metadata through the browser to make a changed broadcast PID persistent. A
fallback logs the saved/live PIDs and channel UUID, without authenticated URLs.
If no safe fallback exists, the existing bounded `audio_pid_missing` retry applies.

## Web configuration

Schema: [web.py](../satip_controller/web.py); generated by `web_config()` in
[provision.py](../satip_appliance/provision.py). Unknown fields are rejected.
The table shows schema defaults for omitted fields. Provisioning explicitly
sets LAN binding (`0.0.0.0:8080`) and derives authentication from saved internal
`lan_access` settings (new installations default to `login-free`),
a 90-second mux timeout and RAM-backed preview. The appliance web wrapper
always launches uvicorn on `0.0.0.0:8080`, regardless of the schema's listen
fields, and validates fresh-configured hosts against current local addresses/hostname
dynamically. The bind defaults below apply to the standalone controller web entry
point, not the appliance launcher.

| Required field | Meaning |
|---|---|
| `version` | Integer, exactly 1 |
| `library` | Same library as the player |
| `management_dir` | Shared library/lease/EPG directory |
| `player_state_dir` | Player status directory; read access only |
| `private_dir` | Web cache, journal, snapshots, process lock |
| `admin_credentials` | Separate backend-admin credentials |
| `web_credentials` | Browser login path; field required even with login disabled |
| `network_uuid` | Tvheadend network UUID, 32 lowercase hexadecimal characters |
| `playback_acl_uuid` | Restricted playback access-entry UUID, same format |
| `mux_timeout` | Scan seconds per mux, greater than 0 and at most 180 |

| Optional field | Default when omitted | Meaning |
|---|---|---|
| `listen_host` | `127.0.0.1` | uvicorn bind address |
| `listen_port` | `8080` | Integer, 1–65535 |
| `allowed_hosts` | `["localhost", "127.0.0.1", "testserver"]` | Nonempty HTTP host-name list; no scheme/port |
| `require_auth` | `true` | HTTP Basic login for UI/API/media |
| `preview_credentials` | Absent | Restricted credentials; omission disables preview |
| `preview_runtime_dir` | `private_dir` | Parent for generated `preview/` media |

Required path fields and supplied preview paths must be absolute. Production
preview should use `/run/satip-web` rather than persistent SD-card storage.
Admin credentials load at startup; browser credentials load only when login is
required, and preview credentials only when configured.

Open `http://APPLIANCE_IP:8080/` on your home LAN. First setup is password-free.
New installations use `lan_access=login-free`, including device controls; setting
a web password enables login for management. The bundled Dropbear disables forwarding.
HTTP Basic does not encrypt traffic. See [security](security.md).

## SAT-IP tuner reassignment

The browser's `satip_tuner` device action queues a root-owned tuner change using
`satip_appliance.tv_source tuner FRONTEND_UUID --apply`. It is restricted to
DVB-S/S2 frontends belonging to the accepted server identity in
`identity/satip-server.json`. Only the active SAT-IP network is reassigned;
channels, candidates, favourites, network identity and access policy are unchanged.
The single enabled frontend and its satellite-position assignment are verified
through the live backend API. Reception policy is copied without frontend
identity or linked/master/slave wiring. The old frontend is disabled first.

`web/satip-tuner-transaction.json` is a root-only durable rollback journal of
frontend policy, source-position assignments and prior first-setup display
metadata. Recovery disables affected frontends before restoring assignments,
then restores the old enabled state and fixed-path setup metadata. A failed
recovery retains the journal. Backend startup resolves it before player/web
activation. A successful change updates `web/setup-state.json.frontend_uuid`
for consistent saved display metadata; frontend configuration remains stored
by Tvheadend and survives reboot.

Live device identity/tuner status is read-only through `GET /api/sources`.
A configured frontend is not necessarily receiving: input data rate separates
receiving streams from tuning attempts without data (for example, a disconnected
satellite cable). Server replacement after first setup is not implemented.

## Alternative TV sources

[Enigma2 reception](enigma2.md) retains separate version-1 source profiles in
`web/tv-source-satip.json` and `web/tv-source-enigma2.json`. Each includes
`network_uuid`, `library` and `candidates`; the Enigma2 profile additionally
includes receiver address/ports, bouquet names and a mux-to-service-reference
map for programme information. No source credentials or arbitrary stream URLs
are accepted. Root selection updates the active generated web network/library
and restarts owned services. The player/channel schema remains unchanged.

New imports additionally retain `enigma2.selected_muxes`: distinct managed mux
UUIDs for the selected bouquets. Ordinary scans and metadata refresh respect
this scope, so retained inputs from deselected bouquets do not return to Available
channels. The full reference map is retained to validate managed backend records
in backups. Legacy profiles without this optional field retain their previous
scan behavior until another import establishes an explicit scope.

When playback ACL numbering grows, management revalidates mapped services
from retained source networks as well as the active network. Every exposed
service must still pass the existing free-to-air/video/audio checks; source
profiles do not grant administrator, DVR or additional playback connections.

## Channel library

Top-level fields are exactly `version`, `channels`, and `favourites`. This
example uses synthetic UUIDs:

~~~json
{
  "version": 1,
  "channels": [{
    "uuid": "11111111111111111111111111111111",
    "name": "Example TV",
    "service_uuid": "22222222222222222222222222222222",
    "mux_uuid": "33333333333333333333333333333333",
    "video": "h264",
    "audio_pid": 5102
  }],
  "favourites": ["11111111111111111111111111111111"]
}
~~~

These identities are illustrative, not working mappings. Each channel has exactly:

- `uuid`: **mapped channel** UUID requested by mpv.
- `service_uuid`: broadcast service UUID used by management.
- `mux_uuid`: containing transponder/multiplex UUID.
- `name`: nonblank string, at most 150 characters, no characters below U+0020.
- `video`: exactly `h264` or `mpeg2`, selecting playback/preview policy.
- `audio_pid`: main normal German audio transport PID, integer 1–8191.

All UUIDs are 32 lowercase hex characters. The catalogue is nonempty with unique
channel UUIDs. Favourites contain 1–500 unique catalogue channel UUIDs in viewing
order. The UI/API submits **service** UUIDs; the library saves **channel** UUIDs.
Use the UI for routine edits rather than hand-editing live data.

## Credentials

Each deployed credential file has exactly this shape:

~~~json
{"username": "REPLACE_ME", "password": "REPLACE_WITH_A_PRIVATE_PASSWORD"}
~~~

Values are nonempty strings without CR, LF, or NUL. Combined admin/playback setup
records are rejected by the application loader. Group write or any permissions
for others are rejected. Fresh appliance provisioning creates service-owned
0600 files in service-owned 0700 directories. The loader also accepts appropriately
group-readable 0640 files, but that is not the fresh-store ownership policy. See
[paths and permissions](operations.md#paths-and-permissions).

## Web-managed OSD settings

The Settings page saves `management_dir/settings.json` atomically with mode 0640
(web-owned, management-group readable). This file stays on persistent data even
when `SATIP_RUNTIME_ROOT` is enabled. Schema:

~~~json
{"version": 1, "osd_timeout_ms": 5000, "osd_language": "en"}
~~~

`osd_language` accepts exactly `en` or `de`. Missing language fields in
existing version-1 files default to English; their saved timeout is preserved.
Missing files also default to English. The player passes the selected language
to the OSD and native startup renderer; the early boot monitor reads the same
persistent settings once available. The renderer starts in English.

For the user-facing control and range, see
[Device settings](device-settings.md#tv-on-screen-display). The player reads
updates during its normal management polling, without retuning or restarting.
Changes apply to the next channel/loading/programme or volume bar; an already
visible bar keeps its deadline. Persistent menus/details do not expire. With no
saved file, legacy defaults remain: five seconds for programmes and `osd_ms` for
ordinary/volume messages. Invalid saved data retains the last valid player preferences. Language changes
refresh open menus/details and programme banners without resetting their state
or extending the banner deadline. Other transient messages update when next shown.

## Saved state and fixed policies

`state.json` holds `version`, last successful favourite `channel`, `volume`
(0–100), and Boolean `mute`. Missing/invalid state defaults to the first favourite,
volume 35, unmuted. Invalid primary configuration fails startup.

Not everything is a JSON setting:

- Backend HTTP is fixed at `127.0.0.1:9981`; streams use `profile=pass`.
- Renderer, H.264 hardware copy decode, MPEG-2 software/BWDIF with mild luma
  sharpening and 720p bicubic scaling, PCM format, and subtitles are fixed
  in [player.py](../satip_controller/player.py). IPC timeout recovery invalidates
  the connection and uses software decoding for the controller lifetime; a service
  restart/reboot tries hardware again. Signal loss alone does not trigger this fallback.
- GPIO selection is `gpio_ir_recv`; key bindings are code-defined. Changing
  keyboard VID/PID also requires adapting the installed udev rule.
- Automatic EPG banners default to five seconds. Saving the web Settings page
  overrides both this duration and ordinary `osd_ms` feedback; see the
  [web-managed settings](#web-managed-osd-settings) above.
- Live TV idle/startup limits are 20/45 seconds, with no maximum viewing duration.
  Heartbeats or successful media requests renew activity; physical input takes
  priority over streaming.
- EPG freshness is five minutes. OSD appearance and layout are code-defined in
  `satip_controller/osd.py`, not JSON settings.
- Satellite, tuner assignment, and transponders belong to [Tvheadend](tvheadend.md).

## Device preferences and helper

The browser's [device controls](device-settings.md) save root-owned preferences in
/data/store/identity/development.txt and /data/store/identity/device.json.
The web login is /data/store/config/web/login.json; password edits synchronize
its protected factory seed. Root password changes persist only a hash.
An unchanged FAT password/SSH recovery seed superseded by a browser edit is
ignored; explicitly editing that seed later still applies recovery on boot.

Unconfirmed Wi-Fi trials use /data/store/network/wifi-trial.json (0600). The root
helper restores interrupted trials before S40network starts WLAN. See
[provisioning](provisioning.md#allowlisted-preferences) for boot-file semantics.
Credentials and Wi-Fi secrets remain protected plaintext: do not publish these
files or private backups.

The unprivileged web service uses fixed actions over /run/satip-device/control.sock,
restricted to root and the web UID. BusyBox init independently respawns the helper.
Diagnostics are in /run/satip-device-helper.log. Do not loosen socket permissions.
Storage selection and player-readiness contracts are in
[Time shifting](timeshift.md#mounting-persistence-and-removal).


## Configuration backup contract

The configured Buildroot appliance exports format `satip-configuration` version 1
as an uncompressed tar archive, maximum 32 MiB. `manifest.json` records the format,
creation timestamp, exact pinned backend revision, persistent schema and per-file
sizes/SHA-256 checksums. The manifest and archive file sets must match exactly.
There are at most 10,000 settings files, each at most 8 MiB. Checksums are not
signatures; only restore trusted archives.

`satip_appliance/backup.py` owns the fixed allowlist: generated player/web
configuration and credentials, library/settings/catalogue/player state, supported
identity/network/input preferences and SAT-IP-only backend configuration. Packed
Tvheadend settings are preserved, with bounded decompression and message parsing
for validation. EPG, media, locks/leases, recovery journals, scan history, update
payloads and boot files are not exported. Unknown paths, links, archive-specified
ownership/modes and arbitrary backend hooks are refused.

Export normalizes effective root/SSH settings, removes any plaintext root-password
seed, and captures current authorized keys. `identity/root-access.json` stores
only the root hash/lock state (version 1); recovery provisioning reapplies it without
importing the full shadow database. Web root-password edits synchronize the record.
Explicit newly edited FAT root recovery preferences still take precedence.
Restore fingerprints unchanged FAT access seeds so they cannot silently overwrite
restored credentials on reboot. Effective network/access files are regenerated,
including an explicitly empty authorized-keys file and absent Wi-Fi configuration.

Validation requires a completed fresh appliance, schema 1 and the pinned backend
revision. It checks fixed generated paths, installed timezone/input preferences,
library structure, account copies/backend passwords and playback access restrictions.
This is not a migration interface for arbitrary Debian or manually edited setups.

The root helper serializes maintenance with device changes, a web mutation gate and
ordered guardian stop/start. Restore stages a full new canonical store, assigns
local UID/GID/modes and fsyncs its data before a fixed-path rename transaction.
`provision.boot()` recovers the durable journal before data preparation: pre-commit
interruption restores the previous store; post-commit uses the new store. USB buffers,
RAM state and EPG refill after reboot. Operational/update history stays local.
See [operations](operations.md#backups) for private staging/rollback paths and
[security](security.md#configuration-backups) for secret-handling boundaries.
